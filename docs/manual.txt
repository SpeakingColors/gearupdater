## Intro
Studio 87 Gear Updater is one window that lists every Studio 87 plugin, VST, FX and app and shows which of them have a newer version on GitHub. You can update one product, several at once, or all of them, and read the changelog of each before you do.
It is free and open source and made mainly for its author, so it is built to be quick: a saved list appears at once, one check of GitHub follows, and every action is one click.
It collects nothing. It checks GitHub only when you open it or click Check for updates. There are no timers, no background checks and no auto-start. The only network use is reading public GitHub data and downloading a release zip you chose to install.

## Quick start
- Open Studio 87 Gear Updater. The list saved last time appears at once and it checks GitHub one time.
- Type in the search box to filter by name, kind or status. Tabs: Updates, All, VST and FX, Synths, Controllers, Apps and logue, Installed, Not installed. The app opens on Updates; on the All tab the products with an update come first, then the rest by name. The list scrolls with the mouse wheel; there are no scrollbars.
- The Updates tab shows what has a newer version. Click Changelog on a row to read what changed.
- Click Update on a row to update just that product. Or tick several rows and click Update selected (only real updates count), Install selected (not-installed products) or Apply selected (a mix, for example "2 updates, 1 install"). Update all acts on the updates in the tab you are viewing; on the Not installed tab the button says Install all.
- Each download is checked against its SHA256 checksums before anything is installed. If a check fails, that product is refused and nothing is changed.
- Close your DAW before updating a plugin, so its file is not in use. Restart the DAW and rescan plugins afterwards.
- Click Check for updates whenever you want to look again. Nothing else asks GitHub anything.

## What is in the zip
Studio87-Gear-Updater-vX.Y.Z.zip holds a linux folder (the Flatpak), a windows folder (the Setup.exe), a macos folder (the .pkg), this manual, INSTALL.txt, LICENSE and SHA256SUMS. A separate SHA256SUMS release asset lists the zip itself, so an older updater can check it.
If the macos folder is missing and the zip holds NO-MACOS.txt instead, the macOS installer was not built for that release. Version 0.1.2 is like that: the macOS build queue was stuck, so v0.1.2 has no macOS package. macOS users cannot install this release; the next release brings it back.
Every installer in it is a normal installer: no scripts to run, no terminal needed (the one terminal line for Linux is an optional alternative).

## Install and remove
Linux (Bazzite, Fedora, Ubuntu and others with Flatpak): double click linux/Studio87-GearUpdater.flatpak, then press Install in your software centre (for example Discover). It needs the KDE runtime and the PySide base app from Flathub; Flatpak fetches them the first time if they are missing. Terminal alternative: flatpak install --user Studio87-GearUpdater.flatpak. Remove it with: flatpak uninstall --user io.github.speakingcolors.Studio87GearUpdater. The Flatpak may use the network, show a window, write ~/.vst3 and run flatpak install on your computer; it cannot see the rest of your home folder.
Windows: run windows/Studio87-GearUpdater-Setup.exe. The app starts as a normal user, without a prompt. Only an All users install asks for administrator rights, once for the whole batch (one UAC prompt); Just for me never asks. Windows may show a blue unknown publisher screen: More info, then Run anyway. Remove it in Settings, Apps, Studio 87 Gear Updater, Uninstall. The uninstaller asks if you also want the updater's own settings deleted (the default is No).
macOS: open macos/Studio87-GearUpdater-macOS.pkg. If macOS blocks it, open System Settings, Privacy and Security, and choose Open Anyway. Remove it by opening Uninstall Studio 87 Gear Updater in the Applications folder. Not available in v0.1.2 (see above).
Honest status: version 0.1.0 was tested on Windows by the author and worked. Nothing in 0.1.2 has been tried on a real machine by anyone yet, and macOS and Linux have not been tested by anyone. The installers are not code-signed or notarised, because certificates cost money and this is a free project. The warning only says not signed by a known company. The code is open on GitHub and SHA256SUMS in the zip lets you check your download.
Updating the updater: it tells you when a newer one exists (Update the updater first). Windows runs the new Setup for you, macOS opens the new .pkg, and the Linux Flatpak shows the command to run. Your settings stay.

## Settings
Look: three looks, Neon Navy, Purple Soda Pop and PurrOne. The look is saved with the app settings. The default is PurrOne.
Hover bubbles: switch the one-second info bubbles on or off.
Install mode: All users (default on Windows and macOS) or Just for me. The app itself always starts without administrator rights; All users asks once per batch, only when a Setup.exe or .pkg has to run. Just for me puts plugins in your own VST3 folder: Windows %LOCALAPPDATA%\Programs\Common\VST3, macOS ~/Library/Audio/Plug-Ins/VST3, Linux ~/.vst3. Choose it if you do not want any administrator prompt.
GitHub account: optional Sign in with GitHub (device code, no permissions). It raises GitHub's hourly limit from 60 to 5000. The token is kept in your system keychain if there is one, otherwise in an encrypted file in the app's own folder (0600, key beside it), otherwise only for this session. A line says which: Signed in, token stored in: OS keychain, local file or this session only. The file is casual protection only: the key sits beside it, so it hides the token from other accounts and from a glance, not from a program running as you. The token is never logged. If the sign in expires the app asks you to sign in again and keeps working without it. Sign out removes it.
Saved list: Clear removes the offline copy of the catalog, product info and screenshots (60 MB cap). Plugin files are never cached for offline use; the one exception is a zip that finished downloading and is waiting for its install (a failed or declined one), which Clear does not remove.
Previous versions: Clear removes the kept older plugin folders (600 MB cap).
Linux plugins go to: Automatic uses the Flatpak extension when that product's extension is already installed and otherwise puts the plugin in the VST3 folder (~/.vst3). VST3 folder and Flatpak DAW force one of the two. Your presets are never touched by either.

## Safety and privacy
- Nothing is installed without your click on Update, Install, Update selected, Install selected, Apply selected, Update all or Install all.
- Every download is verified: GitHub's own SHA-256 digest of the zip, a SHA256SUMS release asset that lists the zip (when the release has one), and the SHA256SUMS inside the zip for every file. At least one source must exist; all that exist must match. On a mismatch the product is refused.
- These checks show that the download is intact and is what the release published. They are not a signature and do not prove who made it.
- Zips and plugin tarballs are unpacked safely: no paths outside the target folder, no symbolic links, and a plugin tarball must contain exactly one .vst3 folder.
- Presets and user data folders are never touched. A zip that finished downloading stays in the cache until its install worked, then it is deleted (leftovers are dropped after a week, and the folder is kept under 2 GB at each check). A plugin update replaces only the plugin's .vst3 folder. Every file is checked against its SHA256 before the installed copy is touched, and checked again after copying; if anything fails the old version is put back by itself.
- Roll back: after an update of a plugin folder the app copied itself, the version you had is kept (last version only). The Roll back button on that row puts it back. A Setup.exe, .pkg or Flatpak runs as it is and has no Roll back.
- Downloads retry up to four times with a growing pause (1.5, 3, 6 and 12 seconds) and resume where they stopped. In Update all one failure never stops the others; a Results list shows each product and Retry failed repeats only the failed ones.
- Administrator rights: one helper per batch re-checks each installer's SHA256 and runs fixed command lines only; it takes no commands or paths from the file it reads.
- Nothing about you or your computer is sent. The requests carry only the generic User-Agent Studio87-GearUpdater, an Accept header and, for saved answers, the If-None-Match header GitHub itself gave out.

## Troubleshooting
- Offline: a bar says Offline, showing saved list from the date of the saved copy. Install and Update are disabled (hover for the reason) unless the installer zip was already downloaded. Click Check for updates when you are back online.
- Update the updater first: a newer Studio 87 Gear Updater exists. Windows runs its Setup and closes this window; macOS opens the .pkg; the Linux Flatpak shows the command to run.
- Plugin link: plugins open this app with studio87://open?product=NAME. Only open and product are read, the product must be in the catalog, nothing is executed, only one window exists.
- GitHub rate limit: the app normally reads one catalog file that is rebuilt every 3 hours, so it does not use the limit. If that file cannot be read it asks GitHub per product (about 50 requests, 60 allowed per hour without an account, 5000 if you sign in). If the limit is reached the app stops asking, shows the saved list, and tells you in how many minutes to try again.
- Installed version unknown: the product has no readable version in its plugin file and was not installed by this updater. After you update it once with this updater, it is known.
- Not set up for updates yet: the row only links to GitHub. Its project page tells you how to get it.
- Guided install: the release has no installer this updater knows how to run for your system, so it downloads and verifies the zip, opens the folder and you follow INSTALL.txt. It never runs scripts it does not know.
- Flatpak DAW does not see the plugin: use Settings, Linux plugins go to, Flatpak DAW, and update again. The DAW must use the same Freedesktop runtime as the extension (see the product's INSTALL.txt).
